# Change-order extraction: approach and limits

The pipeline reads text files directly and extracts text from text-based PDFs page by page. It recognizes a controlled set of common change-order labels, normalizes dates, monetary amounts, and schedule-day counts, and emits a fixed JSON structure. Every extracted value carries its source line, page number, and a rule-based confidence score so a reviewer can trace the result back to the document.

I chose conservative extraction over filling gaps by inference. Missing fields stay `null`; ambiguous dates and malformed values stay unresolved with their evidence; contradictory repeated values are returned as `null` with the conflicting lines preserved. The output is checked against the field contract, and the contract is also provided in `schema.json`. Confidence is a review cue, not a calibrated probability: direct matches score 0.95, unambiguously parsed numeric dates 0.72, labeled but unparseable values 0.25, conflicts 0.20, and absent fields 0.

The main failure modes are scanned PDFs without OCR text, unfamiliar labels or layouts, table columns whose reading order is lost during PDF text extraction, OCR mistakes, ambiguous locale-specific dates, and stale or superseded values that look syntactically valid. The current tool does not infer approval from signatures, resolve document revisions, or calculate contract totals. Low-confidence and conflicting fields should receive human review.

The tests cover a labeled change-order text fixture, a real text-layer PDF fixture read through the CLI from disk, a deliberately corrupt PDF, an image-only/blank PDF signal, pipe-separated fields, values on following lines, schedule-unit normalization, conflicts, ambiguous dates, and malformed amounts. `python scripts/evaluate.py` scores 31 expected field values across four controlled cases and reports mismatches by field. The fixtures are not Sledge customer documents; their 100% exact-match result is a regression check, not a claim about customer-document accuracy. Confidence is lower for values recovered from a following line (0.85) than values directly following a label (0.95); all scores remain heuristic. Before production use, I would measure field-level precision and recall on representative, permissioned documents, calibrate confidence scores, and add OCR or layout-aware parsing based on observed errors.
